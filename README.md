# ONE 泰拳格斗馆小程序

项目使用微信小程序云开发，业务入口是 `cloudfunctions/businessCore`，`quickstartFunctions` 仅用于示例。

## 使用说明

- [管理员使用说明](docs/管理员使用说明.md)：人员权限、套餐管理、权益派发、排期、到场与线下人工核销、门店和看板。
- [客户使用说明](docs/客户使用说明.md)：登录、权益、预约与取消、到店、线下预约和常见问题。

同目录的 HTML 阅读版可直接打开，支持目录跳转和浏览器打印／保存为 PDF。修改 Markdown 后运行 `node tools/render-user-guides.js` 更新 HTML。

## 部署与首次启动

1. 在微信开发者工具中开通或选择云开发环境，把 `miniprogram/app.js` 中的 `globalData.env` 设置为该环境 ID。
2. 右键 `cloudfunctions/businessCore`，选择“上传并部署：云端安装依赖”。该目录的 `config.json` 声明了手机号登录和身份二维码需要的云调用权限。使用 `uploadCloudFunction.sh` 时也会部署此业务函数。
3. 在云开发控制台的 `businessCore` 云函数配置中，设置环境变量 `ADMIN_PHONE_NUMBERS`，值为首位管理员的真实手机号；多个管理员号码用英文逗号分隔。例如 `13812345678,13912345678`。建议将函数执行超时设置为 20 秒，为首次建集合预留时间。
4. 打开小程序并授权手机号登录。管理员号码匹配的是微信接口返回的真实手机号，客户端不能通过传入 `role` 或 `phone` 获得管理员权限。

**部署上传本身不会执行初始化。部署后首次调用 `businessCore` 时，云函数会在查询登录态、手机号登录或业务读写之前自动初始化数据库，不需要先登录管理员，也不需要点击管理页面按钮。**

自动创建以下 9 个集合，并补齐默认门店和套餐配置：

| 集合 | 首次启动数据 |
| --- | --- |
| `app_user` | 空，用户手机号登录或管理员手动录入时创建 |
| `biz_store` | 默认门店 |
| `biz_package` | 默认套餐 |
| `user_asset` | 空 |
| `user_asset_log` | 空 |
| `biz_class_schedule` | 空 |
| `biz_booking` | 空 |
| `user_invite_code` | 空，打开邀请码功能时生成本人邀请码 |
| `user_point_log` | 空，绑定成功时记录双方积分奖励 |

初始化按固定 ID 补齐基础配置，不覆盖已有同 ID 的记录。同一云函数实例共享初始化 Promise；不同实例同时启动时允许重复建集合和重复插入检查。初始化失败会返回 `DATABASE_INIT_ERROR`，后续调用可重试。热实例初始化成功后不再重复初始化；管理员页面的“检查服务”可以再次补齐和校验。

普通号码首次登录为客户。配置的管理员号码下次进行手机号登录时会获得管理员权限，包括已注册的客户账号。未设置 `ADMIN_PHONE_NUMBERS` 不影响普通用户登录；也可在云开发控制台将真实用户的 `app_user.role` 改为 `3`，再重新登录。移除环境变量中的号码不会撤销数据库中已有的管理员角色，后续人员权限由管理员页面管理。

## 演示数据

自动初始化不写入演示用户、课时余额、排课和预约。已有演示记录不会被删除。

仅在测试环境需要旧版演示数据时，将 `businessCore` 的环境变量 `ENABLE_DEMO_SEEDS` 设置为 `true`，然后由已登录管理员点击“检查服务”。该操作会额外补齐演示记录，包括演示管理员；正式环境应保持该变量未设置。`bootstrap` 接口要求管理员身份，首次启动自动建集合不依赖此接口。

## 设计与交互

生产小程序的 16 个页面统一采用深墨色、暖白与朱红，保留 ONE 品牌。首页的团体与专属训练分别进入对应场次；游客可浏览真实排课，登录后回到原预约入口。个人中心优先展示权益与预约，身份码按需展开。

管理员保留管理权限，同时拥有工作台入口，可用自己的账号排课、查看学员名单、派发权益及核销，管理员也会出现在预约大厅的教练筛选中。工作台的“人工核销”支持按姓名或手机号查找已建档学员，登记一次已发生的团课或私教训练；已有场次的名单页也提供“补核销线下学员”。未预约的学员每次扣减对应类型的 1 课时，已有待核销预约则直接确认到场，不重复扣课。余额不足、权益过期、账号停用或无场次权限时拒绝写入；扣课、训练记录和审计流水在同一事务中提交。网络异常会在本地保存未确认请求，重进页面后复用同一请求核对，不能改动待确认参数；同一学员、门店、课程类型和训练分钟也不能重复独立登记。单独登记的训练不会作为开放场次出现在排课列表，学员个人中心与管理员看板可查看记录。尚未建档或没有课时的线下客户须先建立账号并派发权益。

数据页支持加载反馈、失败重试和下拉刷新。预约、退课、派发、核销和排课都以云端写入成功为准，不再退回本地模拟成功。排课使用日期与时间选择器，每周重复明确生成连续 4 周场次；派发与缺席操作会提示具体对象和结果。

管理员可在“看板 → 人员权限管理 → 录入新用户”填写姓名、11 位手机号和营业中的所属门店，建立客户档案。录入不会绑定操作人的微信身份，也不会自动增加课时；可随后派发权益、进行线下人工核销。重复手机号不会覆盖已有档案，网络失败后在同一表单重试会复用请求号。客户使用该手机号授权登录时关联原档案，保留姓名、门店、角色、权益及训练记录。录入与手机号登录共用固定用户 ID，并在事务中重读，避免并发建档覆盖。

后端统一按微信 OPENID 验证身份和角色，检查权益到期、开课时间、预约归属、取消时限、重复核销及排课冲突。看板展示当前门店的当日真实数据，可复制当前展示的权益流水。旧数据无 `expiry_date` 时继续兼容为未设置到期日。

退出登录会在一个事务中清除当前微信身份的全部业务登录绑定，包括已停用账号和历史重复绑定，保留会员账号、权益及预约记录。云端退出成功后，前端清空个人资料、权益、二维码和管理缓存，并将退出状态保存到本地；重启后仍以游客身份浏览，重新手机号登录后恢复正常登录态。云端失败时会保留当前账号并提示重试。退出期间迟到的资料查询不会写回旧数据。

本地布局预览直接渲染页面的 WXML/WXSS，并使用独立示例数据，不调用云函数：

```sh
node tools/preview-miniprogram.js
```

访问 `http://127.0.0.1:4318` 选择页面；`?state=guest`、`?state=empty`、`?state=error` 分别预览游客、空数据和失败状态，管理页的 `?popup=1` 可预览表单弹窗。人员页 `?popup=1&state=duplicate` 可查看重复号码反馈，`?popup=role` 可查看权限调整。人员页 `?popup=assets` 可查看客户套餐详情，结合 `state=expired`、`empty`、`error`、`loading`、`disabled` 查看不同状态。截图位于 `artifacts/design`。此预览用于检查布局，实际微信组件、隐私授权、身份二维码和云端事务仍须在微信开发者工具与真机验收。

人员管理的客户卡片展示团课／私教可用余额，详情展示有效期、过期次数与最近 30 条套餐派发记录；同类型课时合并使用，历史派发名称和到期日通过新流水快照保留。详情每次打开及手动刷新均读取云端，不将读取失败显示成零余额。

前后端统一将内部故障转换为可理解的原因和处理建议，保留具体业务校验；超时写入提示核对结果，不假定失败。原始错误只留在服务日志。提示规则源文件为 `cloudfunctions/businessCore/user-feedback.js`，修改后运行 `node tools/sync-user-feedback.js` 同步小程序副本，回归测试校验一致性。

更新时需重新上传部署整个 `cloudfunctions/businessCore` 目录（包含 `request-policy.js` 和 `user-feedback.js`），并重新编译上传 `miniprogram`。不用清空现有数据库。

参考：[微信云开发文档](https://developers.weixin.qq.com/miniprogram/dev/wxcloud/basis/getting-started.html)、[云调用权限配置](https://docs.cloudbase.net/faq/knowledge/cloud-call-604101-permission-error)。

积分模块入口仅在“我的”页面，不增加底部导航，也不在登录时填写邀请码。“填写邀请码领积分”展开输入框，每个账号首次绑定可领取100积分，邀请人同步获得100积分；绑定后不可更换，不能自邀，停用账号不能获得邀请奖励。已有账号未绑定时也可参与。本人邀请码在“我的积分”中复制，积分余额与最近50条明细实时读取。积分独立于训练权益，当前没有兑换或抵扣功能。

邀请关系、双方积分余额与两条积分流水在同一事务中提交；同一码重试不会重复加分。邀请码按用户生成稳定代码，使用固定代码记录防止冲突覆盖；身份取自微信上下文，忽略客户端指定的人员和奖励数量。新集合仅通过业务云函数读取或写入，应保持客户端不可读写的数据库权限。部署新版业务云函数后首次请求自动补齐新集合，不需要清空历史数据。布局预览支持 `/preview/points?state=empty` 和 `/preview/profile?invite=form`、`bound`、`error`、`loading`。

## 多语言设置

“我的”页面顶部提供语言设置，支持简体中文、英语、法语、泰语、德语、日语、印地语（Hindi）。游客可先选语言，登录页也提供同一设置。首次进入优先识别支持的系统语言，不支持的系统语言显示中文；手动选择保存到当前设备，重启、退出和重新登录不清除该设置。保存失败保留原语言并显示处理建议。

全部18个业务页面、导航标题、底部导航、日期星期、状态标签、选项、确认弹窗与已定义的错误和操作提示支持切换。业务状态仍使用原值；姓名、门店名称、地址、课程名称、套餐名称和备注保持录入原文。官方隐私协议实际名称和内容由微信提供，不做自动翻译。切换语言不更改账号权限、训练权益、积分或已有预约。

词库源文件保留在 `miniprogram/locales/`，由 `project.config.json` 的 `packOptions.ignore` 排除，不打包进小程序；保留稳定目录避免开发者工具仍读取旧文件路径时报 ENOENT。页面静态文案在 `zh-ui.json` 和 `ui-translations.tsv`（列顺序：词条编号、英、法、泰、德、日、印地语）；操作提示在 `messages.tsv`（中文源文、六种外语），同义提示映射在 `feedback-aliases.js`。修改词库后运行 `node tools/sync-i18n.js` 同步生成 `miniprogram/utils/i18n-text.js` 和 `i18n.wxs`。模板通过 WXS 翻译，确认框用 `contentParts` 将录入内容与系统提示分开，勿翻译原始数据或用于判断的状态值。预览URL增加 `lang=en`、`fr`、`th`、`de`、`ja`、`hi` 检查相应布局。

语言功能仅需重新编译、上传小程序，无需单独部署云函数。回归运行 `node --test cloudfunctions/businessCore/test/*.test.js tests/miniprogram/*.test.js`；翻译同步、持久化、参数原文、错误覆盖和生命周期由 `tests/miniprogram/i18n.test.js` 检查。

上传体积通过 `node tools/check-package-size.js` 检查：按 `packOptions.ignore` 排除词库源文件、未注册的云开发示例页、示例组件和示例图片，保留全部业务页面、运行翻译文件及三张场馆照片。源文件预算为 1.8 MB，为编译结果留出余量；最终包大小以微信开发者工具的代码包分析为准。

## 排课调整与操作纠错

“工作台 → 排期管理 → 调整 / 取消”展示受影响客户，可调整尚未开始的场次主题、时间和人数。管理员可更换教练；教练只能调整自己负责的场次。提交校验当前预约名单版本、人数上限及教练时段冲突，保留前后排课快照、原因、操作人和影响名单。客户预约跟随场次更新，并展示调整或取消原因。已开始、有核销或缺席记录的场次不能直接调整或取消，须先核对／纠正记录。

取消先锁定场次，再分批退还所有待核销预约各1课时。每批最多10人，进度持久化于场次，失败回滚当前批；重新打开选择“继续退课”，完成后才提示全部退回。取消中的场次不再接受预约或核销，不延长原权益到期日。

“看板 → 操作纠错”仅管理员可用。撤销预约到场／缺席恢复待核销，不再次退款；撤销直接人工核销退回1课时并作废对应训练。撤销派发扣回本次课时和累计派发，余额不足、后续派发改变有效期或续课重置后有使用时拒绝直接撤销。新派发保存余额／有效期快照；没有快照的历史记录不猜测原余额，明确提示不能自动撤销。撤销保留原记录和原因、操作人、时间、前后余额及状态审计；重试不重复扣／退款。课时纠错不执行线下现金退款。

部署整个 businessCore（含 adjustments.js、request-policy.js、user-feedback.js）并重新编译上传小程序；不新增集合，不清空现有记录。运行完整测试以及 node tools/check-package-size.js；微信原生编译渲染测试通过 WCC_PATH 指定本地 wcc.exe。


## 客户跟进与经营报表

管理员进入“看板 → 客户跟进与报表”，切换客户跟进和经营报表。客户按所属门店筛选；没有所属门店的旧档案按有效派发所在门店关联。停用账号不进入名单，最近到店在全部门店的有效到场记录中核对。

默认提醒未来7天内到期且仍有余课、已购类型有效余额不超过2次、距最近到店或建档超过30天的客户；可修改阈值，也可查看全部客户、按姓名或手机号搜索。未购课类型不误报余额不足，已过期课时显示为不可用。名单展示团课和私教余额、到期日、最近到店日期，并可复制手机号。

经营报表按北京时间的日期范围查询（含首尾日，最多366天）。收款以线下派发的实收金额和登记日期统计；已撤销和零金额赠课不计收入。续费为同一客户同一课种的后续付费购买，历史跨门店购买参与判定；历史顺序无法确认时单独标识。核销、缺席按实际训练日期统计，取消或已撤销核销不计入。教练报表展示排课、取消、已完成、到场、人工核销和授课分钟；授课时长仅计算已结束且有到场的正式排课，独立人工训练只计人次。历史记录缺少日期会提示，并从对应统计排除。读取失败不显示虚假的零收入。

“导出 CSV”生成当前完整查询结果，包含全部符合条件的客户，或经营汇总、每日数据、教练情况及收款明细，不受页面每次展示30条限制。表头使用当前语言，用户录入内容保持原文。文件通过微信文件选择界面分享；不支持文件导出的设备可“复制表格”粘贴到Excel。公式开头的文本按普通文本保护，手机号前导零保留。条件变化后先重新查询，再导出。

部署整个 businessCore（包含 reports.js）并重新编译上传小程序，不新增集合、不清空数据。可运行 node --test cloudfunctions/businessCore/test/*.test.js tests/miniprogram/*.test.js 以及 node tools/check-package-size.js 验证。真实云环境需验收权限、数据量下的查询时长和手机文件导出。


## 自选时间的专属预约与限期无限次套餐

专属训练现在由客户在“预约 → 专属训练”查看全部启用的教练（沿用教练、管理员可授课的设置），选择教练和未来七天内的日期，再自行选择同一天的开始、结束时间。结束须晚于开始，不限于60分钟。页面展示该教练当天已占用时间；服务器检查全部门店的教练冲突及客户已有预约。无须先发布私教课，预约成功自动建立1人专属场次，出现在客户预约、教练排期和核销名单。客户仍需私下与教练确认安排，系统不代发消息。取消沿用开课前超过2小时的规则，取消后释放时间；原已发布场次和已有预约保留历史。

专属预约写入前将原请求保存到当前账号的本机记录；网络结果不明时显示“核对原预约”，复用原请求确认，不可改动原请求时间。已确认的业务失败释放请求，允许重新选择。后台幂等记录避免重试产生额外场次或扣课。

管理员“套餐管理 → 新建套餐”可选择团课／私教，再选择“按次数”或“期限内无限次”。无限次无需填次数，但须填写价格和有效天数；派发页仍可核对实际到期日。无限次权益从派发当天生效，到期日当天可用。重复派发保留新旧无限次到期日中较晚日期，次数与无限次分别保留有效期，不互相覆盖。按实际训练日期判断期限，优先使用有效无限次权益；到期后仅可使用仍有效且有余额的次数权益。

预约、人工核销、客户退约、场馆取消与误核销纠错按原记录实际消费方式处理。无限次不扣次数，取消也不增加次数；之前用次数预约的课，后来购买无限次套餐，取消仍退还当时扣掉的次数。调整日期不可超出该预约的权益期限。无限次误派发在未使用且没有较新无限次派发时可撤销，恢复原期限并保留审计；已用于预约或核销时提示先核对训练记录。无限次套餐在首页、我的、客户详情、派发、客户跟进、经营报表和CSV中分别展示，实收与续费仍正常统计。

部署整个 businessCore，包括 entitlements.js、private-booking.js、adjustments.js、reports.js 和提示规则，再重新编译上传小程序。无需清空记录或新增集合，旧次数套餐和预约继续按原扣退次数处理。


## 教练介绍、资料编辑与头像上传

客户在“预约 → 专属训练”查看紧凑教练列表，首页最多展示3位；点击“查看全部”打开搜索面板，按姓名、头衔或擅长筛选，每批显示20位、下滑继续显示。点击教练行查看介绍，行尾“选择”直接选择，选中后首页仅保留该教练，可“更换教练”。介绍页可查看头衔、资历、擅长、个人介绍、荣誉与照片／证书，点击照片查看大图。“选择这位教练”返回原预约页并保留日期。教练停用或身份改为客户后，介绍页不再展示，预约仍由服务器校验。

教练及可授课管理员从“我的 → 我的教练资料”编辑本人的公开资料，表单分为“基本资料、介绍与荣誉、照片与证书”，切换分区保留全部草稿。擅长和荣誉每行一项、各最多10项，介绍最多2000字符，照片最多6张。文字与相册点击“保存教练资料”后才公开，保存失败保留草稿，重新读取前确认丢弃未保存内容。后台忽略客户端指定的人员，校验当前微信身份和资料版本，避免旧页面覆盖新修改。介绍页不返回手机号、微信身份或权益数据。

所有登录账号均可在“我的”上传头像；教练资料编辑页也有同一入口，头像保存后立即同步到我的及预约教练卡片。照片选择支持相册和相机，优先压缩至头像800px／照片1600px长边，单张上传文件不超过2MB，支持JPG、PNG、WebP；图片存在云存储，不进入小程序主包。部分上传失败保留已成功的照片草稿，取消选择不提示失败。移除相册照片只移除公开引用，不自动删除云文件，以免旧页面或历史引用失效；后台可定期整理不再引用的文件。

部署整个 businessCore（包含 coach-profile.js）并重新编译上传小程序，无需新增集合或清空数据。云存储保存于 profile-media/<账号散列>/，后台只接受当前环境、当前账号目录的有效图片。云存储需允许客户读取公开图片、上传者写入自己的文件；可在仅存公开图片的环境使用“所有用户可读，仅创建者可写”，不要设置所有人可写。权限与微信隐私指引的上线步骤见 [图片上传部署说明](docs/图片上传部署说明.md)。
