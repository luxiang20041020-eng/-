# 预约与返还安全检查

本轮修复了以下已确认问题：

- 调课只检查教练冲突，未检查受影响客户的其他预约。现同时检查客户与教练时间重叠，首尾相接仍允许。
- 预约与调课的冲突扫描缺少共同事务冲突点。现使用 `user_asset_log/_reservation_timeline_guard` 隐藏控制文档序列化预约与调课；该记录 `is_deleted=true`，不参与业务流水、经营报表和客户记录。事务失败不保留控制记录或部分扣款。
- 过期套餐续费重置后，撤销旧人工核销会把旧课时返还到新余额。现重置时记录 `count_generation`，预约/人工核销保存当时批次。旧批次返还保存在 `expired_refund_count` 和流水中，不能作为新套餐可用课时。续费撤销会恢复原批次。旧数据未带批次的兼容值为空；具有原到期日期的旧记录也执行到期判断。
- 场次缺失结束时间、非法人数或异常次数余额时，原比较表达式可能因 NaN 放行。现提交前明确拒绝，失败不扣课、不占名额。

确认保留的规则：以北京时间训练开始日期判断套餐有效期；到期当天可预约训练，次日起失效。取消只允许开课前超过2小时，正好2小时不可取消。次数套餐按实际扣除返还一次，无限次预约不扣次数、取消不虚增余额。场馆取消按持久化名单分批返还，重试不重复退课。

新增乐观事务模拟支持文档版本冲突、原子提交和重试，覆盖不同客户抢最后一个名额、不同教练重叠课、团课与专属交叉冲突、同教练专属预约、重复私教请求、重复取消、调课与预约并发、套餐期限以及旧核销纠错返还。它是本地模拟，不代替真实云数据库的并发验证或压测。

上线需重新部署 `businessCore` 并编译发布小程序。没有新增集合；批次及过期返还字段均为兼容的可选字段。本轮未改动线上余额或执行真实预约。
