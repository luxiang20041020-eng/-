# 图片上传部署说明

1. 在微信开发者工具重新部署整个 cloudfunctions/businessCore，选择云端安装依赖；目录须包含 coach-profile.js、request-policy.js、user-feedback.js 及其他现有模块。随后重新编译并上传 miniprogram。无需新增数据库集合或清空原数据。
2. 在当前云开发环境的“存储 → 权限设置”中配置公开教练照片可供客户读取、文件创建者可以上传和管理自己的文件。如果此环境仅存放公开图片，可采用“所有用户可读，仅创建者可写”；对应微信规则示例为 { "read": true, "write": "resource.openid == auth.openid" }。保持其他现有私有文件的权限需求；不要开放所有人写入。参考 [CloudBase 云存储安全规则](https://docs.cloudbase.net/storage/security-rules)。
3. 在微信公众平台的小程序“用户隐私保护指引”中声明头像及教练照片上传用途，并包含实际使用的照片选择接口。新版上传入口会在微信要求时显示协议与原生同意按钮；拒绝会取消本次选择，不修改原资料。
4. 用教练账号上传头像、训练照片、证书并保存，再用客户账号进入专属训练，检查头像、荣誉、照片大图和“选择这位教练”。验证取消选择、断网、过大图片时原资料仍保留，并确认客户不能调用教练资料编辑接口。

图片目录是 profile-media/<账号散列>/，文件名每次上传不同。后台检查账号目录、当前环境及图片是否存在；头像和教练资料分别校验版本。照片存于云端，不会增加小程序上传包中的本地图片数量。

相册移除只移除资料中的引用，不自动删除实体文件。可以在云开发控制台定期核对 app_user 的 avatar_url 和 coach_photos 后，整理已无任何引用的旧图片。
