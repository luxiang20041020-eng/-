# **🥊 泰拳搏击馆小程序：数据库与主要视图设计文档**

本文档基于业务 PRD 进行技术侧拆解，定义了支撑“多门店、离线交易、双向核销、排课模板”等核心业务的底层数据模型与前端视图结构。

## **一、 数据库结构设计 (Database Schema)**

建议采用关系型数据库（如 MySQL 8.0+）。以下表结构中，所有表建议默认包含 created\_at (创建时间)、updated\_at (更新时间) 和 is\_deleted (软删除标记) 字段，下表中省略展示以保持简洁。

### **1\. 用户与权限模块**

**表名：sys\_user (用户信息表)**

| 字段名 | 数据类型 | 约束/索引 | 描述说明 |
| :---- | :---- | :---- | :---- |
| id | BIGINT | PK, AUTO\_INC | 用户唯一ID |
| openid | VARCHAR(64) | UNIQUE | 微信 OpenID |
| phone | VARCHAR(20) | INDEX | 手机号码 |
| real\_name | VARCHAR(50) |  | 真实姓名 |
| avatar\_url | VARCHAR(255) |  | 头像地址 |
| role | TINYINT | INDEX | 角色：1-客户，2-教练，3-管理员 |
| home\_store\_id | BIGINT |  | 默认归属门店ID (用于默认数据筛选) |
| status | TINYINT |  | 状态：1-正常，0-禁用 |

### **2\. 门店与基础配置模块**

**表名：biz\_store (门店表)**

| 字段名 | 数据类型 | 约束/索引 | 描述说明 |
| :---- | :---- | :---- | :---- |
| id | BIGINT | PK, AUTO\_INC | 门店唯一ID |
| name | VARCHAR(100) |  | 门店名称 (如：高新旗舰店) |
| address | VARCHAR(255) |  | 详细地址 |
| longitude | DECIMAL(10,6) |  | 经度 (用于地图导航) |
| latitude | DECIMAL(10,6) |  | 纬度 |

**表名：biz\_package (课程套餐展示表)**

*注意：此表仅用于首页价格公示及教练发课时的快捷选项，不参与在线交易。*

| 字段名 | 数据类型 | 约束/索引 | 描述说明 |
| :---- | :---- | :---- | :---- |
| id | BIGINT | PK, AUTO\_INC | 套餐ID |
| name | VARCHAR(100) |  | 套餐名称 (如：30节私教卡) |
| asset\_type | TINYINT |  | 给客户增加的资产类型：1-团课，2-私教 |
| course\_count | INT |  | 包含的课时数 |
| display\_price | DECIMAL(10,2) |  | 展示标价（元） |
| status | TINYINT |  | 状态：1-上架，0-下架 |

### **3\. 客户资产与审计模块 (核心风控)**

**表名：user\_asset (用户课时资产表)**

| 字段名 | 数据类型 | 约束/索引 | 描述说明 |
| :---- | :---- | :---- | :---- |
| id | BIGINT | PK, AUTO\_INC | 资产记录ID |
| user\_id | BIGINT | INDEX(联合) | 客户ID |
| asset\_type | TINYINT | INDEX(联合) | 资产类型：1-团课，2-私教 |
| balance | INT | \>= 0 | **当前剩余可用课时数** (核心状态) |
| total\_earned | INT |  | 累计获得课时数 (用于统计) |

**表名：user\_asset\_log (资产流水表 \- 严格防篡改)**

| 字段名 | 数据类型 | 约束/索引 | 描述说明 |
| :---- | :---- | :---- | :---- |
| id | BIGINT | PK, AUTO\_INC | 流水ID |
| user\_id | BIGINT | INDEX | 客户ID |
| operate\_type | TINYINT |  | 操作：1-教练派发(增加)，2-预约扣减，3-取消退还，4-系统作废 |
| amount | INT |  | 变动数量 (带正负号，如 \+30 或 \-1) |
| operator\_id | BIGINT |  | 操作人ID（如果是用户预约，填user\_id；如果是教练发课，填教练id） |
| ref\_biz\_id | BIGINT |  | 关联业务ID（如：排课ID，或套餐ID） |
| remark | VARCHAR(255) |  | 备注（如：“微信转账已收6000”、“客户缺席核销”） |

### **4\. 排课与核销模块**

**表名：biz\_class\_schedule (排课主表)**

| 字段名 | 数据类型 | 约束/索引 | 描述说明 |
| :---- | :---- | :---- | :---- |
| id | BIGINT | PK, AUTO\_INC | 排课ID |
| store\_id | BIGINT | INDEX | 所在门店ID |
| coach\_id | BIGINT | INDEX | 上课教练ID |
| class\_type | TINYINT |  | 课程类型：1-团课，2-私教 |
| title | VARCHAR(100) |  | 课程主题 (如：泰拳基础) |
| start\_time | DATETIME | INDEX | 课程开始时间 |
| end\_time | DATETIME |  | 课程结束时间 |
| max\_capacity | INT |  | 最大人数 (私教默认为1) |
| booked\_count | INT |  | 已预约人数 (用于并发控制) |
| status | TINYINT |  | 状态：1-可预约，2-已满员，3-已结束，4-教练已取消 |

**表名：biz\_booking (预约与核销记录表)**

| 字段名 | 数据类型 | 约束/索引 | 描述说明 |
| :---- | :---- | :---- | :---- |
| id | BIGINT | PK, AUTO\_INC | 预约ID |
| schedule\_id | BIGINT | INDEX(联合) | 关联排课ID |
| user\_id | BIGINT | INDEX(联合) | 预约用户ID |
| status | TINYINT |  | 状态：1-待核销(已扣课)，2-已核销(正常上课)，3-客户取消(已退课)，4-教练取消(已退课)，5-客户缺席(未退课) |
| writeoff\_time | DATETIME |  | 实际扫码/签到核销时间 |

## **二、 主要视图设计 (View & UI Architecture)**

整体采用底部 TabBar 导航结构，根据用户角色动态显示不同的 Tab。

### **1\. 全局 TabBar 结构**

* **客户 (Client)**: \[首页\] \- \[预约大厅\] \- \[我的\]  
* **教练 (Coach)**: \[首页\] \- \[预约大厅\] \- **\[工作台\]** \- \[我的\]  
* **管理员 (Admin)**: \[首页\] \- \[预约大厅\] \- **\[数据看板\]** \- \[我的\]

### **2\. 客户核心视图设计**

**V1. 首页 (Home View)**

* Header: 门店切换下拉组件 \[高新店 ▽\]。  
* Banner: 管理员配置的轮播图或跑马灯公告。  
* ActionGrid: 核心功能金刚区（团课预约、私教预约、我的课表）。  
* InfoSection: 馆内实景图、教练团队展示（水平滑动）。  
* PriceList: 课程套餐标价展示（纯展示，底部按钮为“拨打客服电话”或“复制客服微信”）。

**V2. 预约大厅 (Booking View)**

* DateSelector: 顶部水平日历轴（周一、周二...），默认选中今日。  
* Filter: 团课/私教 切换 Tab，以及教练筛选。  
* ClassList: 列表渲染 biz\_class\_schedule。  
  * 卡片数据：时间、课程名、教练名、进度条 (已约人数/总人数)。  
  * 状态按钮：【立即预约】(绿色)、【已满员】(灰色)、【已结束】(灰色)。  
* Action: 点击【立即预约】弹出确认框（“将扣除 1 节团课/私教，确定预约？”）。

**V3. 身份核销码组件 (QRCode Modal)**

* 入口：在\[我的\]页面或浮动按钮点击唤出。  
* 逻辑：生成一个包含用户唯一标识及高频动态刷新时效（如30秒更新一次）的二维码。用于教练扫码。

### **3\. 教练核心视图设计 (工作台 Tab)**

**V4. 课时派发页 (Asset Distribution View) \- 【防飞单核心页面】**

* Input: 扫描客户身份码 或 搜索客户手机号。  
* UserInfo: 展示目标客户头像、姓名、当前剩余课时（防充错人）。  
* Form:  
  * **充值套餐**：单选（30节私教、半年团课等）。  
  * **实收金额 (必填)**：输入线下实际收取的金额（用于对账）。  
  * **收款方式 (必填)**：下拉选择（微信转账、支付宝、POS机、现金）。  
  * **备注**：选填。  
* Action: 按钮【确认派发，给客户加课】（后台触发写入 user\_asset 和 user\_asset\_log）。

**V5. 课程核销与签到页 (Check-in View)**

* Header: 当前课程信息（时间、课程名）。  
* Action: 大按钮【扫码核销】（唤起微信扫一扫，扫描客户的个人码）。  
* StudentList: 预约此课的客户列表。  
  * 列表项包含：客户头像、姓名、状态（待核销 / 已核销）。  
  * 教练可侧滑列表项，点击【手动签到】或标记为【缺席】。

**V6. 排课管理页 (Schedule Management View)**

* Calendar: 日历视图，可点击具体日期。  
* TimeSlots: 类似于滴滴司机的排班表，点击对应的空闲时间块。  
* AddClassModal:  
  * 设置课程类型（团课/私教）。  
  * 设置容量（1\~50）。  
  * 开启“存为模板”选项，允许“应用到未来四周的相同时间”。

### **4\. 管理员核心视图设计**

**V7. 财务与发课审计视图 (Audit Dashboard)**

* DataCards: 今日新增私教课时数、今日新增团课课时数、今日核销总课时数。  
* LogList: 资产流水明细表。  
  * 展示格式：\[时间\] \[教练名\] 为 \[客户名\] 派发了 \[30节私教卡\]，备注：微信收款6000元。  
  * 支持按“教练”进行过滤，方便管理员每天与前台财务流水对账。

## **三、 关键接口 (API) 设计建议**

| 接口路径 (RESTful) | 描述 | 请求核心参数 | 备注 |
| :---- | :---- | :---- | :---- |
| POST /api/auth/login | 微信授权登录 | wx\_code | 返回 token 及角色权限 |
| POST /api/coach/asset/distribute | 教练给客户派发课时 | user\_id, package\_id, remark, offline\_amount | **需加分布式锁，防重复发课** |
| POST /api/client/booking/create | 客户预约课程 | schedule\_id | **需扣减课时资产，数据库需开启事务** |
| POST /api/client/booking/cancel | 客户取消预约 | booking\_id | 需校验是否超过最晚取消时间限制 |
| POST /api/coach/booking/writeoff | 教练核销课程 | booking\_id 或 user\_qrcode | 更新状态为“已核销” |
