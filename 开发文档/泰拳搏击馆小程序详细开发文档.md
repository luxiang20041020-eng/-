# **🥊 泰拳搏击馆微信小程序产品需求与开发文档 (PRD)**

## **1\. 项目概述与核心定位**

本项目旨在为泰拳搏击馆提供一套轻量、高效的门店运营管理工具。

**核心约束条件**：因无对公账户，小程序**绝对不包含**微信支付（JSAPI）功能。所有资金交易在线下（微信转账、支付宝、现金、POS机）完成。

**系统核心价值**：实现“客户资产管理（课时）”、“多门店排课预约”、“教练工作流自动化”以及“上课核销数据化”。

## **2\. 角色与权限模型 (RBAC)**

系统采用严格的基于角色的访问控制。一个微信用户（OpenID）对应一个账号，但拥有不同身份标签。

| 角色 | 权限范围与核心职责 |
| :---- | :---- |
| **客户 (Client)** | 默认角色。浏览排课、预约课程（团课/私教）、查看剩余课时、查看上课记录、切换门店。 |
| **教练 (Coach)** | 包含客户所有权限。额外拥有：发布/管理自己负责的排课（使用模板）、扫码核销客户课程、**给客户手动派发课时（代充值）**、查看本人带课的数据统计。 |
| **管理员 (Admin)** | 最高权限。统筹多门店数据。可发布首页公告、制定/上架课程套餐（用于展示）、赋予普通用户“教练”或“管理员”权限、查看全馆核销对账数据。 |

**深度思考（风控点）**：既然由“教练”给客户发课，存在教练私下收钱发课的“飞单”风险。因此系统必须引入\*\*“课时派发审计日志”\*\*，管理员端可以随时查看“谁、在什么时间、给哪个客户、派发了什么套餐”。

## **3\. 核心业务流程闭环**

### **3.1 线下交易与资产派发流程（替代支付）**

1. 客户在线下门店支付费用。  
2. 教练（或前台）打开小程序【工作台】，点击【课时录入】。  
3. 教练让客户出示小程序内的**个人身份二维码**，或直接输入客户手机号检索。  
4. 教练选择对应的“课程套餐”（如：30节私教课 / 半年团课卡），点击确认派发。  
5. 系统自动在客户账户内增加对应资产，并生成一条不可篡改的流水记录。

### **3.2 排课与预约流程**

* **团课 (Group Class)**：教练发布时间段（如周三 19:00-20:30，泰拳基础），设定人数上限（如15人）。客户消耗1个团课课时进行预约。满员则进入候补状态（V2.0规划）。  
* **私教 (Private Class)**：教练在后台设置自己的“可约时间块”（如每周一至周五 10:00-18:00）。系统自动将这些时间切分为1小时/节的空闲档期。客户选择档期预约，消耗1个私教课时。

### **3.3 签到核销流程 (Write-off)**

采用 **“双向核销”** 机制，确保严谨：

* **方式A（主动扫码，推荐）**：客户到店，打开小程序出示“预约核销码”。教练使用小程序【扫一扫】功能扫描该码，系统扣减1个课时，状态变为“已完成”。  
* **方式B（教练代核，防忘带手机）**：教练打开该节课的“预约名单”，直接勾选已到场的客户，点击“批量核销”。系统触发模板消息通知客户“您的XX课已核销”。

## **4\. 功能模块详细设计**

### **4.1 客户服务端 (Client UI)**

* **首页 (Home)**  
  * **门店切换组件**：顶部左侧（如：XX搏击馆-高新店 / 经开店），切换后下方数据全部刷新。  
  * **公告跑马灯/Banner**：展示管理员发布的最新公告（如放假通知、赛事战报）。  
  * **快捷功能区**：团课预约、私教预约、我的课表、价格公示（仅展示，引导线下联系）。  
* **预约大厅 (Booking)**  
  * 按日期（横向日历滑动）展示当日所有课程。  
  * 支持按“团课/私教”、“指定教练”进行筛选。  
  * 展示课程详情：课程内容、教练介绍、剩余名额。  
* **我的 (Profile)**  
  * **课时资产卡片**：直观展示“剩余私教课：X节”、“剩余团课：X节”。  
  * **个人身份码**：点击放大，用于给教练扫码派课。  
  * 我的预约（待上课、已取消、已完成）。  
  * 上课统计（本月上了几节课，坚持天数）。

### **4.2 教练工作台 (Coach Workspace) \- 仅限教练身份可见**

* **排课管理 (Schedule Management)**  
  * **模板排课**：支持创建“周排课模板”。一键将模板应用到接下来的 1周/2周/4周，避免每周重复点选。  
  * 临时调课：支持取消单节课程（系统自动退还已预约客户的课时，并发送微信通知）。  
* **客户管理 & 课时录入 (Asset Entry)**  
  * 扫码录入/手机号搜索客户。  
  * 操作为客户添加对应的课时套餐（必填备注：如“微信收款”或“前台POS机”）。  
* **今日带课 & 核销 (Today's Classes)**  
  * 按时间轴展示今日自己负责的所有课程。  
  * 进入单节课，查看报名名单，进行扫码核销或手动点名核销。

### **4.3 管理后台 (Admin Dashboard) \- 手机端轻量管理**

* **套餐与定价管理**  
  * 设置系统中存在的资产类型：团课次卡、私教次卡。  
  * 配置对外展示的“套餐价目表”（如：新人体验课1节 9.9元，私教30节 6000元），供客户在首页查看。  
* **人员与权限管理**  
  * 搜索客户微信，将其身份提升为“教练”。  
  * 教练离职时，可一键解除教练权限。  
* **运营看板 & 审计 (Analytics & Audit)**  
  * 查看各门店今日预约人数、实到人数。  
  * **资产流水审计**：查看所有教练派发课时的记录表（时间、操作人、接收人、派发数量），用于财务线下对账。  
  * 发布系统公告文本/图片。

## **5\. 核心数据模型 (Database Schema) 建议**

为保证系统的扩展性，数据库设计需包含以下核心表：

1. Users (用户表): ID, OpenID, 手机号, 姓名, 头像, 角色(client/coach/admin), 归属主门店ID.  
2. Stores (门店表): ID, 门店名称, 地址, 经纬度, 状态.  
3. User\_Assets (用户资产表): ID, User\_ID, 资产类型(团课/私教), 剩余数量, 累计获取数量.  
4. Asset\_Logs (资产流水表): ID, User\_ID, 操作类型(充值/扣减/退还), 变动数量, 关联单号, 操作人\_ID(防作弊审计).  
5. Class\_Packages (套餐配置表): ID, 套餐名, 类型(团课/私教), 课时数, 标价, 状态(上架/下架).  
6. Classes (排课主表): ID, 门店ID, 教练ID, 类型, 开始时间, 结束时间, 容量, 已预约数, 状态.  
7. Bookings (预约记录表): ID, User\_ID, Class\_ID, 预约时间, 核销状态(待核销/已核销/已取消/用户缺席), 核销时间.

## **6\. 异常边界与深度规则思考（重点开发必看）**

1. **防刷课漏洞（并发问题）**：当客户只剩 1 节课时，如果他在网速慢时疯狂点击两节不同的课，后端必须加锁（Redis 分布式锁或数据库乐观锁），防止课时扣成负数。  
2. **取消规则（防占坑）**：必须设定“最晚取消时间”。例如：开课前 2 小时内不可取消。如果客户不到场，教练核销时标记为“缺席”，**照常扣除课时**。如果不设此规则，优质课程资源会被白白占用。  
3. **教练请假与紧急停课**：如果有客户已经预约，教练突发情况需要取消课程。系统必须：  
   * 自动将该节课绑定的所有客户的预约状态改为“系统取消”。  
   * 自动将课时原路退回给客户。  
   * 触发微信服务通知（需提前收集模板消息 FormID 授权）告知客户停课。  
4. **跨店通用规则**：用户的课时资产是跟人不跟店的。系统设计上，用户在A店买的课，如果预约B店的课，是允许扣除的。（如果业务上不允许跨店，需要在 User\_Assets 表中增加 Store\_ID 字段进行强绑定隔离）。
